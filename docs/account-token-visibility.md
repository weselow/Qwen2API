# Сохранённые аккаунты и срок действия токена

В режимах `DATA_SAVE_MODE=file` и `redis` сохранённые аккаунты остаются
в списке управления независимо от срока действия их токена. При старте
приложение не выполняет автоматический вход для таких записей. Это позволяет
видеть и вручную обслуживать аккаунт, даже если Qwen временно отклоняет вход.

Для исходящих запросов ротация отдельно проверяет наличие, формат и срок
действия JWT при каждом выборе аккаунта. Истёкший или отсутствующий токен
не становится пригодным для запросов только потому, что запись видна в UI.
Успешный явный refresh заменяет токен, после чего аккаунт может снова
участвовать в ротации. Режим загрузки аккаунтов из `ACCOUNTS` (`none`)
сохраняет прежнее поведение входа.

Это изменение не обходит отказ Qwen при входе и не гарантирует, что токен,
срок которого ещё не истёк, будет принят сервером Qwen. Автоматический
refresh во время работы и настройка его расписания этим изменением не меняются.

При восстановлении записей, удалённых старой версией только из памяти,
обновлённое приложение загрузит прежний файл данных. Не нужно повторно
добавлять эти аккаунты через логин/пароль или заменять их токены.

После исправления Qwen2API-0ef явное удаление из интерфейса сохраняется
в file/Redis. В file-режиме обновляется и recovery backup, включая пустой
список после удаления последнего аккаунта. При ошибке записи аккаунт остаётся
в памяти и ротации; API возвращает ошибку вместо ложного подтверждения.
Отложенная статистика и старые batch-снимки не восстанавливают удалённую
запись. Повторное добавление остаётся явной операцией пользователя.
Само обновление версии существующие аккаунты не удаляет.
